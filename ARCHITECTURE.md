# Форман — устройство приложения

Помощник бригадира HVAC (Сан-Диего). Один код на Expo для iPhone, Android и веба.
Интерфейс на русском; английский и испанский подключаются позже через словарь.

## Структура

```
src/
  app/                      маршруты expo-router (только тонкие файлы)
    _layout.tsx             корень: запускает синхронизацию, стек поверх вкладок
    +html.tsx               HTML-обёртка веб-версии (lang="ru", ссылка команды)
    (tabs)/_layout.tsx      нижние вкладки и иконки
    (tabs)/index.tsx        «Смена»      -> src/features/training
    (tabs)/library.tsx      «Установки»  -> src/features/library
    (tabs)/laws.tsx         «Законы»     -> src/features/laws
    (tabs)/sklad.tsx        «Склад»      -> src/features/sklad
    (tabs)/more.tsx         «Ещё»        -> src/features/settings
  features/                 экраны и логика разделов
    training/               обучение на смене + общая «Заметка смены»
    library/                библиотека установок (в разработке)
    laws/                   правила Калифорнии (в разработке)
    sklad/                  кнопка открытия веб-склада FixPro
    settings/               код команды, язык, о приложении
    work/                   ТЕСТ: импорт смены из веб-пилота dot v0.3 (import-v03.ts + карточка в «Ещё»)
    jobs/                   объекты смены (только на устройстве): модель, хранилище, фото (IndexedDB),
                            копия файлом: backup-model.ts (чистая логика), backup-store.ts, backup-card.tsx
  components/               общие элементы: ui.tsx (экран, кнопка, поле), sync-badge.tsx,
                            update-banner.tsx («Есть обновление» веб-версии)
  lib/
    i18n.ts                 t(key) — тексты; RU заполнен, EN/ES берут RU
    storage.ts              хранилище на устройстве (AsyncStorage; в браузере — localStorage)
    sync-core.ts            ядро синхронизации без React Native (его же проверяет тест)
    sync.ts                 общий клиент синхронизации для приложения + хук useSyncStatus()
    theme.ts                цвета, крупные шрифты, кнопки ≥ 56 px
    sw-update.ts            веб: регистрация service worker и состояние «Есть обновление»
public/sw.js                service worker (шаблон; версию и список файлов подставляет scripts/sw-stamp.mjs)
tests/sync.test.mjs         проверка синхронизации на настоящей базе
tests/import-v03.test.mjs   проверка импорта JSON пилота v0.3 (данные — tests/fixtures, вымышленные)
```

Новый экран раздела кладётся в `src/features/<раздел>/`, а в `src/app/` — только файл-маршрут.

## Синхронизация

- **Команда** = ID команды + секретный код (личных входов пока нет). Код вводится во вкладке
  «Ещё»: ссылка `…#s=<команда>&k=<код>` или «ID код» через пробел. Проверка — функцией базы `space_info`.
- **Сначала устройство.** `saveDoc / deleteDoc` всегда сразу пишут на устройство и помечают запись
  «не отправлено». Если команда подключена — тут же отправляют в базу. Нет связи — данные остаются на
  устройстве и уходят позже: при возврате в приложение, при появлении сети (веб) и раз в 30 секунд.
- **Чтение.** `getDoc / listDocs` при связи берут свежие данные из базы, но неотправленные локальные
  правки важнее. Без связи — локальная копия.
- **База.** Только функции Supabase (RPC) по HTTPS: `space_info, doc_list, doc_get, doc_set,
  doc_delete`; каждая сама проверяет код команды. Коллекции «Формана» в базе имеют префикс `fm_`
  (например `fm_shift`), чтобы не смешиваться с коллекциями «Склада» той же команды.
- **Статус** (строка под формами): только на устройстве / синхронизация / синхронизировано /
  не отправлено N / нет связи / неверный код. Функции синхронизации никогда не бросают ошибку в экран.
- **Склад.** Вкладка «Склад» открывает https://sorvingbel-hue.github.io/fixpro-sklad-app/ ; если команда
  подключена, — сразу на этой команде (код передаётся после `#`, на сервер страницы не уходит).
- Телефон и веб-версия работают с **одной и той же базой**: одна команда видит одни и те же данные.

## Настройка

Адрес и публичный ключ базы — в файле `.env` (в git не попадает, образец — `.env.example`):

```
EXPO_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
EXPO_PUBLIC_SUPABASE_KEY=sb_publishable_...
```

## Запуск на телефоне (Expo Go)

1. Установить Expo Go из App Store / Google Play.
2. На компьютере: `npm install`, затем `npx expo start`.
3. iPhone: навести камеру на QR-код в терминале. Android: отсканировать QR в Expo Go.
   Если телефон в другой сети: `npx expo start --tunnel`.

## Веб-версия

- Разработка: `npm run web`.
- Сборка для тестеров: `npm run web:export` → папка `dist/` (статичные страницы). Её можно выложить на
  любой статический хостинг (GitHub Pages, Netlify). Для адреса в подпапке (например `/forman/`)
  добавить в `app.json` → `expo.experiments.baseUrl`.
- Ссылка `https://<сайт>/#s=<команда>&k=<код>` сразу подключает тестера к команде; код убирается
  из адресной строки.

## Копия файлом и второй телефон (М7)

- Объекты и фото живут только на телефоне (localStorage `fm.jobs.v1`, `fm.job.<id>.work`; фото — IndexedDB
  `forman-photos`/`blobs`, ключи `<id>:full` и `<id>:thumb`). Чтобы они не пропали и чтобы перенести их на второй
  телефон — карточка «Копия и второй телефон» в списке объектов.
- «Сохранить копию (файл)» → `forman-kopiya-ГГГГ-ММ-ДД-ЧЧММ.forman.json`:
  `{kind:'forman-backup', v:1, createdAt, app:'forman', jobs, works:{[jobId]:WorkV03Doc}, photos:{[photoId]:dataURL JPEG}}`.
  Пример (ДЕМО) в копию не входит. Если браузер умеет `navigator.canShare({files})` — кнопка «Отправить копию»
  (AirDrop, WhatsApp, «Файлы»), иначе файл скачивается. Время копии — `fm.backup.last`; если есть объекты,
  а копии нет или ей больше 3 дней — в карточке «Сделайте копию».
- После скачивания «Формана» не знает, сохранил ли человек файл (в Safari есть «Отмена»), поэтому дата копии
  записывается только после нажатия «Файл сохранён». После «Отправить копию» — сразу (меню «Поделиться» завершилось).
- «Загрузить копию» строго проверяет файл (`parseBackup`): kind/v; объект — id из простых символов, настоящая дата
  создания, тексты не длиннее пределов (`FILE_LIMITS`, длинное обрезается), у фото — простые id и числа;
  «Работа» — `sanitizeWork` (work-model.ts): только документ этого объекта, позиции/вопросы без id или не объекты
  отбрасываются, недостающие поля — пустые; фото — только data:image JPEG/PNG/WebP. Файл больше 150 МБ не читается.
  Даты из будущего: если копия «из будущего» (часы того телефона спешат), все её даты сдвигаются назад на эту
  разницу, ни одна дата не позже «сейчас», датам такого файла не верим (см. ниже) и показываем предупреждение.
- Слияние (`planMerge`) — по частям объекта, у каждой своё время правки, чтобы правки с двух телефонов не затирали
  друг друга:
  - поля (название, № заказа, заметка и незнакомые поля новых версий) — более свежие по `editedAt`
    (его ставит `patchJob`; у старых записей — `updatedAt`);
  - фото — объединяются; id удалённых фото хранятся в `removedPhotos` (до 200), такие фото не возвращаются
    и стираются на другом телефоне; фото с id чужого фото этого телефона пропускаются. Больше 60 фото после
    слияния — ничего не выбрасывается, человек получает предупреждение;
  - «Работа» (`mergeWork`) — более свежий по `updated` документ главный, позиции и вопросы, которых в нём нет,
    добавляются, пустые поля позиции заполняются из другого, отметки этапов объединяются, заметки — обе;
  - если часы телефона с копией спешат — при расхождении остаётся своё, новое из файла добавляется.
  Сравнивается содержимое, а не даты: повторная загрузка того же файла и обмен копиями туда-обратно ничего не меняют.
- Порядок записи (`restoreBackup`): фото в IndexedDB (долго — на экране «Загружаю фото: N из M», список объектов
  в это время не открывается и не меняется) → план слияния заново по свежим данным телефона → «Работа» → список.
  Если запись не поместилась — всё записанное возвращается как было, фото этой загрузки стираются:
  «ничего не изменено». Итог: «Загружено: N объектов, M фото; пропущено: K» и пояснения.
- `normalizeJobs` и `normalizeWork` сохраняют незнакомые поля: старая версия, сохраняя объект, не стирает поля,
  которые добавила новая. Экран объекта обёрнут в `JobGuard`: если данные объекта всё же испорчены — вместо белого
  экрана «Объект не открылся», «Все объекты» и «Удалить этот объект».

## Без сети (service worker, только веб-сборка)

- `public/sw.js` попадает в `dist/sw.js`; `npm run web:export` после `expo export` запускает `scripts/sw-stamp.mjs`,
  который подставляет версию (хэш файлов сборки) и список файлов для кэша (страницы вкладок, `_expo/static`, `assets`,
  иконки, manifest — ≈4 МБ). Без этого шага новая сборка не будет замечена как обновление — публиковать только
  результат `npm run web:export`.
- Регистрация — в `src/lib/sw-update.ts` (из корневого `_layout` через `UpdateBanner`): только веб и только
  продакшен-сборка; в разработке (`__DEV__`) SW не ставится, а оставшийся — снимается. Scope — `/fixpro-sklad-app/forman/`.
- Главное правило: на телефоне всегда ОДНА версия целиком — и страницы, и код из кэша `forman-sw-<версия>`
  (сначала кэш). Новую сборку браузер замечает по новому `sw.js` (проверка мимо HTTP-кэша при каждом открытии,
  при возврате в приложение и раз в 30 минут), скачивает целиком в новый кэш (не скачался хоть один файл —
  установка не удалась, неполный кэш удаляется) и ждёт: «Есть обновление — нажмите, чтобы обновить» →
  `SKIP_WAITING` → перезагрузка; или новая версия включается сама, когда «Форман» полностью закрыли и открыли.
  Так не бывает «страница новой сборки, код старой» (белый экран без сети при переходе на вкладку) и «то новая,
  то старая версия» (старый код переписал бы данные новой). При включении новой версии старые кэши `forman-sw-*`
  удаляются; другие открытые вкладки со старым кодом сами перезагружаются через ~1 с.
- Страница, которой нет в сборке (незнакомый адрес), — из сети, в кэш не кладётся; без сети — главная.
  Ключи кэша — без `?query`. Запросы вне папки «Формана» («Склад»), к другим сайтам (`*.supabase.co`) и не-GET
  SW не трогает. Если `sw.js` не прошёл через `sw-stamp` (метка версии на месте) — SW ничего не кэширует.
- Данные на телефоне (localStorage, IndexedDB) обновление не трогает.
- Аварийно выключить SW: выложить вместо `sw.js` файл из шапки `public/sw.js` (в `install` — `skipWaiting()`,
  в `activate` — удалить кэши `forman-sw-*`, `self.registration.unregister()` и перезагрузить вкладки).

## Проверки

- `npm run typecheck` — TypeScript.
- `npm run test:jobs`, `npm run test:work`, `npm run test:backup` — модели объектов, «Работы» и копии файлом (Node, без базы).
- `npm run test:sync` — создаёт временную команду в настоящей базе, проверяет сохранение, чтение,
  список, работу без связи, второе устройство, удаление и стирает временную команду.
- `npm run test:import-v03` — JSON пилота dot v0.3 → проверка правилами valid() пилота и лимитами →
  временная команда → коллекция `fm_work_v03` (id = job) → сверка поле за полем → space_wipe.
  `PILOT_APP_JS=<app.js пилота>` дополнительно сверяет правила с оригинальной valid(). Фото пилота
  (IndexedDB браузера) в JSON не входят и не переносятся.
- Правила: схему базы не менять; команду `demo` только читать; `.env` не коммитить.
